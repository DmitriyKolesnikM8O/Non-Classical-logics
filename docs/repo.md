# Где лежит проект и как собрать

## 1. Репозиторий и локальная копия

Исходный код проекта размещён на GitHub:

```text
https://github.com/DmitriyKolesnikM8O/Non-Classical-logics.git
```

Локальная копия на машине разработчика:

```text
C:\Users\user\Documents\Non-Classical-logics
```

Клонирование:

```bat
git clone https://github.com/DmitriyKolesnikM8O/Non-Classical-logics.git
cd Non-Classical-logics
```

## 2. Структура проекта

```text
Non-Classical-logics/
├── main.py                  # запуск графического интерфейса
├── pyproject.toml           # описание пакетов и зависимостей
├── requirements.txt         # зависимости для установки
├── src/
│   ├── fuzzy_core/          # библиотека нечетких вычислений
│   ├── logger/              # журналирование
│   └── gui/                 # графический интерфейс
├── tests/                   # автоматические тесты
├── logs/                    # файлы журналов
└── docs/                    # документация и сборка в Word
    ├── intro.md             # задание
    ├── theory.md            # формулы и их назначение
    ├── program.md           # описание программы
    ├── mapping.md           # место формул в программе
    ├── repo.md              # этот раздел
    ├── user_guide.md        # руководство пользователя
    ├── api.md               # программный интерфейс
    ├── Титульник.docx       # готовый титульный лист
    └── build_docx.py        # сборка Markdown → DOCX
```

## 3. Требования

| Компонент | Версия | Назначение |
| --- | --- | --- |
| Python | 3.10 и выше (проверено на 3.13) | среда выполнения |
| numpy | 2.1 и выше | матрицы сходства и замыкание |
| matplotlib | 3.9.2 и выше | графики в интерфейсе |
| pytest | 8.3 и выше | тесты (необязательно) |
| python-docx | 1.1.2 и выше | сборка документации (необязательно) |
| pypdf | 5.0 и выше | работа с PDF-материалами (необязательно) |

На Windows команда `python` может быть заглушкой Microsoft Store. Надёжнее
использовать `py` или явный путь к интерпретатору виртуального окружения:
`.venv\Scripts\python.exe`.

## 4. Сборка окружения (один раз)

```bat
py -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m pip install -e .
```

Команда `pip install -e .` устанавливает пакеты `fuzzy_core`, `logger` и `gui`
в режиме разработки: изменения в `src/` сразу видны без переустановки.

## 5. Запуск программы

```bat
.venv\Scripts\python.exe main.py
```

Другой каталог журналов:

```bat
.venv\Scripts\python.exe main.py --log-dir D:\logs
```

Если пакеты не устанавливались, `main.py` сам добавляет каталог `src` в путь
поиска модулей, поэтому запуск из корня проекта работает и без установки.

## 6. Проверка тестами

```bat
.venv\Scripts\python.exe -m pytest
```

Ожидаемый результат — все тесты пройдены (на момент написания документации
538 проверок). Отдельные группы:

```bat
.venv\Scripts\python.exe -m pytest tests\test_clustering.py
.venv\Scripts\python.exe -m pytest tests\test_gui_clustering.py
```

## 7. Сборка документации в Word

Документация собирается из Markdown-файлов каталога `docs` в один файл:

```bat
.venv\Scripts\python.exe docs\build_docx.py
```

Результат по умолчанию:

```text
docs\Неклассические_логики_документация.docx
```

Порядок разделов задан в `DEFAULT_SOURCES`:

```text
intro.md → theory.md → program.md → mapping.md → repo.md → user_guide.md → api.md
```

Титульный лист берётся из файла `docs\Титульник.docx` и вставляется в начало
документа. Перед сборкой файл можно отредактировать в Word — при следующей
сборке изменения сохранятся. Содержание по умолчанию — поле TOC Word: при
открытии документа Word сам подставляет разделы и номера страниц (обновить
вручную можно по `F9`). Полезные ключи:

| Ключ | Что делает |
| --- | --- |
| `--output путь.docx` | сохранить в другой файл |
| `--sources a.md b.md` | изменить порядок и состав разделов |
| `--toc text` | обычный список заголовков вместо поля TOC |
| `--toc none` | собрать без содержания |
| `--title-page путь.docx` | взять другой титульный лист |
| `--no-title-page` | собрать без титульного листа |

**Важно:** если итоговый файл открыт в Word, сборка завершится ошибкой
`PermissionError`. Закройте документ или сохраните результат во временный файл
ключом `--output`.

## 8. Быстрая проверка после сборки

1. Открыть итоговый `.docx` в Word.
2. Убедиться, что первая страница — титульный лист, а нумерация страниц
   начинается со второго листа.
3. Проверить, что в содержании присутствуют разделы «Задание»,
   «Теоретический раздел», «Описание программы», «Место математических формул
   в программе», «Где лежит проект и как собрать», «Руководство пользователя»
   и «Описание программного интерфейса (API)».
4. Содержание — поле Word: при открытии оно обновляется автоматически; если
   этого не произошло, выделите его и нажмите `F9`.
